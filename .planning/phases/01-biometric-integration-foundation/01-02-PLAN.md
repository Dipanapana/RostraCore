  <behavior>
**Verification Engine (verification.py):**

Core function: `verify_face_embedding(stored_embedding: list[float], verification_embedding: list[float]) -> dict`
- Calculates cosine similarity between two 512-dimensional vectors
- Returns `{"confidence": float, "distance": float}` where confidence = (1 - cosine_distance) * 100
- Two identical vectors -> confidence = 100.0
- Two orthogonal vectors -> confidence = 0.0

Orchestrator function: `process_verification(employee_id: int, verification_embedding: list[float], gps_data: dict | None, db: Session) -> dict`
- Loads stored encrypted template for employee
- Calls verify_face_embedding
- Gets adaptive threshold for employee
- Determines status: "success" (>= threshold), "success_with_warning" (70-threshold), "failed" (< 70)
- Logs VerificationAttempt to database
- Returns: `{"status": str, "confidence": float, "threshold": float, "requires_hr_review": bool}`

Test cases (verification):
- identical embeddings -> confidence ~100, status "success"
- similar embeddings (cosine distance 0.1) -> confidence ~90, status "success"
- borderline embeddings (cosine distance 0.2 with 85% threshold) -> confidence ~80, status "success_with_warning", requires_hr_review=True
- dissimilar embeddings (cosine distance 0.4) -> confidence ~60, status "failed"
- zero-length embedding -> raises ValueError
- wrong dimension embedding -> raises ValueError

**Adaptive Threshold (adaptive_threshold.py):**

Core function: `get_adaptive_threshold(employee_id: int, db: Session) -> float`
- Default threshold: 85.0
- Query VerificationAttempt for employee in last 30 days
- Count attempts where success=True AND confidence >= 90.0
- If count >= 10: return 80.0 (relaxed)
- If 3+ consecutive recent failures: return 85.0 (revert even if previously relaxed)
- Otherwise: return 85.0

Implementation note: The specific numbers (10+ verifications, 30-day window, 3 consecutive failures,
80% relaxed threshold) are the adaptive algorithm details. From the user's perspective, the observable
behavior is: employees who consistently verify well get a more forgiving threshold, and employees
who start failing get stricter checks immediately.

Test cases (adaptive threshold):
- new employee (0 verifications) -> 85.0
- employee with 5 successful high-confidence verifications -> 85.0 (not enough)
- employee with 10+ successful 90%+ verifications in 30 days -> 80.0 (relaxed)
- employee with 10+ successes but 3 recent consecutive failures -> 85.0 (reverted)
- employee with 10+ successes from 60 days ago (outside window) -> 85.0 (expired)
- employee with 10+ successes at 88% confidence (below 90%) -> 85.0 (not high enough)
  </behavior>
  <implementation>
**verification.py:**
- Use numpy for cosine similarity: `1 - (np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))` (numpy already in requirements.txt)
- Input validation: check embedding length matches expected dimensions (512 for FaceNet512), check non-zero vectors
- Do NOT import DeepFace here - verification.py works with raw embeddings (DeepFace is used only during enrollment/capture in enrollment.py)

**adaptive_threshold.py:**
- Pure SQLAlchemy queries against VerificationAttempt model
- Use `datetime.utcnow() - timedelta(days=30)` for rolling window
- For "3 consecutive failures": query last 3 attempts ordered by created_at DESC, check if all have status="failed"
- Return float threshold value
