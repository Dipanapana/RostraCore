## Accomplishments
- Replaced 3N per-assignment `db.query(Shift/Site/Client)` calls in revenue-vs-cost with a single joined query using `joinedload(shift).joinedload(site).joinedload(client)` — applies to both client and time-period grouping branches
- Added `joinedload` import from `sqlalchemy.orm` to reports.py
- confirm_roster endpoint now creates a `Roster` record before the assignment loop: queries shift date range, generates unique `roster_code`, flushes to get `roster_id`
- Each successfully confirmed `ShiftAssignment` is linked to the Roster via `sa.roster_id`, with `status='confirmed'`, `is_confirmed=True`, and `confirmation_datetime` set
- Roster stats (`assigned_shifts`, `unassigned_shifts`, `total_cost`) computed and committed atomically after the full loop
- confirm response now includes `roster_id` and `roster_code` fields

## Decisions Made
- `db.flush()` used (not `db.commit()`) before the assignment loop so roster_id is available for FK linking while keeping the entire confirm operation atomic until the final `db.commit()`
- `outerjoin` used for Client (site may not have a client) — assignments are still included
- Roster `status` set to `"draft"` on creation (lifecycle progresses via separate publish flow)
- `roster_code` uses `uuid4().hex[:6].upper()` suffix for collision-free unique codes within the same month
