## Gaps Summary

One gap was found that blocks the phase goal at scale.

**Gap: N+1 queries in PDF report endpoints** — The JSON `GET /revenue-vs-cost` endpoint was correctly fixed with `joinedload` chaining. However, three PDF export endpoints (`export_profitability_pdf`, `export_revenue_by_client_pdf`, `export_coverage_pdf`) in `reports.py` were not updated and still contain per-assignment/per-shift DB query loops. For 1000 assignments, `export_profitability_pdf` makes approximately 3001 queries — far above the <2s threshold stated in Success Criterion 4.

The phase PLAN truth "The revenue-vs-cost report endpoint uses a single bulk query per grouping" applies to the `/revenue-vs-cost` JSON endpoint, which passes. The PDF variants are separate endpoints and their N+1 behaviour is a gap in the overall goal of "no N+1 queries in reports."

All 4 dashboard endpoints (executive, operations, financial, people-analytics) are fully corrected and should run without crashes. The `/roster/confirm` endpoint correctly creates a Roster record, links ShiftAssignments, and returns `roster_id`. All model field names used across dashboards and reports have been verified against the actual SQLAlchemy column definitions.
