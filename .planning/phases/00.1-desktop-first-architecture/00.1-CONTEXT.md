# Phase 0.1: Desktop-First Architecture - Context

**Gathered:** 2026-02-04
**Status:** Ready for planning

<domain>
## Phase Boundary

**REVISED SCOPE:** Desktop-first architecture with offline capabilities for office-based users. Mobile (React Native) is deferred to a future phase.

**What this phase delivers:**
- Tauri desktop app with full offline mode (roster management, attendance approval work without internet)
- Local data storage and background sync when connection returns
- Complete admin experience on desktop (HR, rostering, real-time monitoring, payroll)
- Foundation for future React Native mobile app (Phase TBD)

**Explicitly OUT of scope for this phase:**
- Mobile PWA/React Native app (future phase)
- Phone camera biometrics (future phase with mobile)
- Mobile-specific UI (future phase)

</domain>

<decisions>
## Implementation Decisions

### Desktop Use Cases
- **Primary users:** Office-based managers, HR admins, finance teams
- **Full admin experience:** Roster management, HR administration, real-time monitoring, payroll processing
- **Desktop = command center:** All capabilities available on desktop

### Desktop Offline Mode
- **Full offline mode required:** Office internet is not always reliable
- **Offline-capable actions:**
  - Roster changes (reassign shifts, adjust schedules) - works offline
  - Attendance approval (approve/reject timesheets) - works offline
- **Online-only actions:**
  - Employee changes (adding/editing employee data) - requires connection
  - Payroll processing (calculations) - requires connection
- **Data caching:** Claude decides what data to cache locally for offline access (likely: current rosters, employee info, recent attendance)

### Desktop Sync Strategy
- **Sync behavior:** Claude decides (automatic background sync vs manual with prompt)
- **Offline UI indicators:** Claude decides (banner/toast vs feature disable indicators)
- **Local storage:** Claude decides (SQLite vs IndexedDB/cache - Tauri context)

### Platform Strategy
- **Desktop-only features:** Payroll processing, System administration (user management, settings, integrations)
- **Multi-platform features (for future):** Attendance, Roster viewing, Approvals, Employee management (when mobile is built)
- **Concurrent sessions:** Claude decides (allow desktop + mobile simultaneously vs single session)
- **Real-time sync:** Claude decides (WebSocket/polling vs periodic vs manual refresh)

### Mobile (Future Phase - Deferred)
- **Technology:** React Native (NOT PWA)
- **Team:** Assemble mobile development team later (recruit best minds for React Native)
- **Biometrics:** Phone camera facial recognition deferred to mobile phase
- **Timeline:** TBD after desktop is complete

### Claude's Discretion
- Local database approach (SQLite, IndexedDB, or hybrid)
- Sync mechanism (automatic, manual, or hybrid)
- Offline UI/UX patterns (banners, disabled states, indicators)
- Data caching strategy (what to sync, how much to keep locally)
- Multi-device session handling
- Real-time vs periodic sync for desktop-to-desktop updates

</decisions>

<specifics>
## Specific Ideas

- "Organizations are office-based, computer-based - desktop must work offline for when internet drops"
- "Roster changes and attendance approval are critical - must work offline"
- "Payroll and admin config need internet - acceptable to require connection"

</specifics>
