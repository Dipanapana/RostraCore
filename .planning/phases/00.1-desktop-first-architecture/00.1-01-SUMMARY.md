## Decisions Made

**1. Use sqlx directly instead of tauri-plugin-sql Pool API**
- Rationale: tauri-plugin-sql v2 doesn't expose SqlitePool in the expected way. Research document patterns used v1 API. sqlx gives us direct control.

**2. Store full JSON in data_json column**
- Rationale: Preserves all API fields without requiring schema migrations when backend adds fields. Flexible for different entity types.

**3. Enable WAL mode in first migration**
- Rationale: Default DELETE journal mode blocks concurrent reads/writes. WAL allows readers and writers to proceed concurrently, critical for background sync.

**4. INSERT OR REPLACE pattern for caching**
- Rationale: Simpler than ON CONFLICT UPDATE syntax. server_id UNIQUE constraint makes this safe.

**5. Fix frontendDist path to ../../frontend/out**
- Rationale: Tauri config is at desktop/src-tauri/, so ../frontend/out was incorrect. Frontend is at root level, requires ../../
