## Decisions Made

**1. Use idb-keyval instead of raw IndexedDB API**
- Rationale: Simpler promise-based API, only 500 bytes gzipped, sufficient for cache persistence

**2. 7-day cache retention (gcTime) and 5-minute staleness**
- Rationale: Balances offline capability with data freshness - most desktop users check in within a week

**3. offlineFirst network mode for queries**
- Rationale: Desktop users expect instant loads - show cached data immediately, update in background

**4. online network mode for mutations**
- Rationale: Mutations should pause when offline rather than fail immediately, resume when connection restored

**5. QueryProvider as outermost provider**
- Rationale: Query cache needs to wrap all other providers to enable data fetching in AuthProvider, ThemeProvider, etc.
